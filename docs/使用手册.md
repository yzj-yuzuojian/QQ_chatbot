# 使用手册

面向**使用者**（客户）的说明书。也供运营方回答客户问题时参考。

---

## 一、三分钟上手

### 第 1 步：添加机器人

在 QQ 里搜索机器人，或者由运营方把你加入体验名单。

> QQ 个人主体的机器人有人数限制（通常 20 个体验名额）。
> 如果加不上，联系运营方。

### 第 2 步：绑定你的 API key

私聊机器人，发送：

```
/setkey
```

它会回一个链接：

```
https://你的绑定页/bind?code=4FF9D7
```

点开链接，粘贴你的 key（`sk-` 开头），点「验证并绑定」。

成功后页面会显示余额，并尝试自动关闭。

> **为什么不在 QQ 里直接发 key？**
> QQ 的聊天记录会永久留存，等于把密钥抄送给第三方。
> 网页绑定更安全，链接 10 分钟内有效，用过即失效。

### 第 3 步：选模型

```
/model
```

它会列出**你这个 key 实际有权限的**模型（不是全部模型）。按序号选：

```
/model 1
```

### 第 4 步：开始聊

直接发消息，不用加命令。

```
我养了一只橘猫叫团子
```

之后它会记住这件事。

## 二、它记得什么

这是它和普通机器人最大的区别。

### 三层记忆

| 层 | 内容 | 例子 |
|---|---|---|
| **事实卡** | 关于你的关键信息，永久保存 | "养了猫：团子"、"对芒果过敏" |
| **摘要** | 每 20 轮对话压缩一次 | "最近在准备字节的面试，压力大" |
| **近期细节** | 最近 2500 条消息，语义检索 | "团子昨天把花瓶打碎了" |

### 实际效果

```
（三个月前）你：我养了一只橘猫叫团子
（今天）    你：我那只猫咋样了
            它：团子啊，它最近没闯祸吧？
```

它能从「我那只猫」联想到「团子」，这是**语义检索**，不是关键词匹配。

### 什么时候会去查记忆

不是每句话都查（那样又慢又贵）。只在你说的话涉及"过去"时才查：

| 会查 | 不会查 |
|---|---|
| 还记得我之前说的吗 | 你好 |
| 我养了什么 | 今天天气不错 |
| 我那只猫咋样了 | 哈哈哈 |
| 我之前说过我喜欢什么 | 嗯 |

实测：只有约 22% 的消息会触发检索。

### 你可以自己管它记的东西

```
/facts              看它记得你什么
/facts set 生日 3月15日    手动告诉它一条
/facts del 生日      删掉一条
```

它自己提炼的事实和你手动加的分开标记，**自动提炼不会覆盖你手动加的**。

## 三、人设：它可以是任何角色

**没有内置角色。** 你自己写，想让它是谁就是谁。

### 新建一个人设

```
/persona new 雪球 你是一只橘猫，名字叫雪球，说话简短，偶尔用"喵"
```

格式：`/persona new <名字> <描述>`

- 名字：≤ 12 字
- 描述：4–2000 字

### 看所有人设

```
/persona
```

会列出你所有的人和当前在用哪个。

### 切换

```
/persona 2          按序号
/persona 雪球        按名字（支持模糊匹配）
```

### 管理

```
/persona edit 2 新的描述    改第 2 个
/persona rename 2 新名字    改名
/persona del 2             删除（要二次确认）
/persona off               不用人设，回到默认
/persona example           看写法示例
```

**上限 5 个。** 删除不可恢复。

### 关键设计：换人设不串味，但记得你是谁

```
人设「雪球」（猫）  ──┐
                     ├── 各自的对话记录
人设「老周」（发小）──┘
                     
事实卡 ───────────────── 共享（"你叫林晚、养了猫"）
```

从「猫」切到「发小」，之前的对话不会混进来，但它**始终记得你是谁**。

### 写人设的技巧

好的描述包含四个要素：

| 要素 | 例子 |
|---|---|
| **身份** | "你是我大学室友，现在在杭州做设计" |
| **关系** | "我们认识六年了，说话很随便" |
| **说话方式** | "说话简短，爱用省略号，不爱用感叹号" |
| **边界** | "不会主动问隐私，不打听收入" |

**反例**（太空泛，效果差）：

```
你是一个温柔体贴的助手
```

**正例**：

```
你叫老周，我大学室友，现在杭州做设计。
我们认识六年，说话很随便，你经常吐槽我但会帮我。
说话简短，爱用省略号，不爱用感叹号。
不知道的事就说不知道，别编。
```

## 四、语气：只改说法，不改人设

```
/mood          看所有语气
/mood 温柔      按名字换
/mood 3        按序号换
```

8 种：如常 / 温柔 / 毒舌 / 话少 / 俏皮 / 黏人 / 暖 / 正经

**和人设的区别**：

- 人设 = 它是谁（身份、关系、背景）
- 语气 = 它怎么说（遣词、句子长短、情绪浓度）

同一个人设可以换不同语气，不用重写人设。

## 五、画图

它可以根据你的描述生成图片。

### 先配置生图 key

```
/setimage
```

点开链接，粘贴**能生图的** key。

> **为什么聊天 key 不能用来画图？**
> 中转站里聊天和生图通常是两个不同的分组授权。
> 实测：某 key 聊天正常，调生图接口返回
> 「分组 gemini 下模型 gpt-image-2 无可用渠道」。

### 用

直接说就行，不用命令：

```
画一只橘猫在窗台上晒太阳
给我画张风景图
```

它会先回一句（3 秒内），图生成好再发过来（30–60 秒）。

### 它怎么知道要画图

由 AI 判断，不是关键词匹配。实测：

| 你说 | 会不会画 |
|---|---|
| 画一只橘猫 | ✅ 画 |
| 给我画张风景图 | ✅ 画 |
| 你好 | ❌ 不画 |
| 我今天很累 | ❌ 不画 |
| **你能发图片吗** | ❌ **不画**（问能力 ≠ 要画） |

### 没配 key 会怎样

```
你：画一只猫
它：好嘞，马上给你画一只小猫。

    （想画图得先配生图 key，发 /setimage。...）
```

**它会明确告诉你画不了，不会假装画好。**

### 成本

生图按张计费，**用你自己的 key 付费**，比聊天贵不少。

- 一张 1024×1024 约 ¥0.15–0.3（取决于你的中转站）
- 平台方不承担这笔费用

## 七、它做不到什么

**这一节很重要**，避免你误解。

### ❌ 不能定时提醒

```
你：明天 6 点叫我起床
它：好，明早 6 点叫你         ← ← 这是谎话，它做不到
```

**原因：** QQ 的被动回复只能在客户发消息后 60 分钟内使用。7 小时后发消息需要「主动消息」权限，每月配额很少。

**目前它仍会口头答应。** 如果你需要提醒，请自己设闹钟。

### ❌ 不能主动找你

只有你先发消息，它才能回。它不会：

- 早上主动说「早啊」
- 几天不聊主动问「最近还好吗」
- 提醒你 key 快过期了

### ❌ 看不懂你发的图片

它只能生成图片，不能理解你发过去的图片内容。

### ❌ 没有语音

不能发语音，也不能听语音。

### ⚠️ 群里不确定

群聊代码写了，但**没有在真实群测试过**。如果要拉进群，建议先小范围试试。

### ⚠️ 群里各聊各的

群里每个人是独立对话线，它不知道其他成员说了什么。

## 八、隐私与数据

### 它存什么

| 内容 | 是否加密 |
|---|---|
| 你说的话、它回的话（原文） | ❌ 明文（要用来检索） |
| 提炼出的事实（"养了猫"） | ❌ 明文 |
| 对话摘要 | ❌ 明文 |
| **你的 API key** | ✅ **加密**（Fernet） |

### 存在哪

运营方服务器上的一个数据库文件。不传第三方，不做用户画像，不卖数据。

### key 怎么用

只在你自己的对话里，直接发给中转站。不经过第二个人。

### 打码

密码、身份证号、银行卡号这类内容，**存储前会替换成 `[密钥]`** 标记。

代价是它确实"记不住"这类信息 —— 但它本来也不该记。

### 你的权利

```
/export    导出你的全部数据（JSON 文件）
/forget    永久删除全部对话和记忆（不可恢复）
/delkey    删除 key，记忆保留
```

### 存多久

一直存，直到你 `/forget`。没有自动过期 —— 因为"记得你"就是这个功能的意义。

## 九、常见问题

### 「它怎么不回复我？」

按顺序检查：

1. **配了 key 吗？** 发 `/model`，如果提示未绑定就是没配
2. **key 还有钱吗？** 发 `/stats` 看余额
3. **模型还在吗？** 你的中转站可能下架了某个模型，发 `/model` 重新选
4. **输入太长？** 单条消息上限 800 字
5. 以上都正常 → 联系运营方

### 「它记错了我说的」

用 `/facts` 看它记了什么，手动改：

```
/facts del 错的类别
/facts set 正确类别 正确内容
```

### 「我想换个角色但保留记忆」

记忆是跟着**你**的，不是跟着人设的。直接新建或切换人设即可，事实卡会保留。

### 「我 key 换了怎么办」

```
/delkey       先解绑旧的
/setkey       绑定新的
/model        重新选模型
```

记忆不受影响。

### 「生图很慢」

正常 30–60 秒。它会先回文字让你知道在处理。

### 「怎么让它忘掉某件事」

```
/facts del 类别        删单条事实
/facts clear           清空所有自动提炼的
/forget                全删（含对话记录，不可恢复）
```

### 「能同时用多个人设吗」

不能同时，但可以随时切换。每人最多存 5 个。

### 「为什么有时候回得慢」

正常 2.5–3.5 秒。慢可能是：

- 上游中转站拥堵
- 用了推理模型（思考过程很慢）
- 生图（30–60 秒）

## 十、给运营方的话

### 客户最常问的三个问题

1. **「我要怎么开始？」** → 发 `/start`
2. **「我没 key 怎么办？」** → 需要自己去中转站注册充值，没有免费方案
3. **「它怎么不回复？」** → 大概率是 key 失效或余额耗尽

### 每天该看什么

```bash
# 服务是否正常
sudo systemctl is-active qq-companion

# 内存（应 < 100MB）
sudo systemctl status qq-companion | grep Memory

# 有异常吗（应该是 0）
sudo journalctl -u qq-companion --since "1 day ago" | grep -c Traceback

# 有漏传 msg_id 吗（应该是 0，非 0 会吃主动配额）
sudo journalctl -u qq-companion --since "1 day ago" | grep -c "无 msg_id"

# key 巡检
.venv/bin/python -m companion.cli check-keys
```

### 需要提前告知客户的事

上线时建议主动说明这几点，避免后续扯皮：

1. **要自己准备 key**，且有余额才能用
2. **不能定时提醒**（这是最容易误解的）
3. **不能主动找你**
4. **生图要单独配 key**，按张收费
5. **`/forget` 不可恢复**

### 排查用的日志关键字

```bash
[gw]          网关（连接、心跳）
[in]          收到的消息
[chat]        对话处理
[vector]      向量索引
[draw]        生图
[image]       图片发送
[bind]        绑定
[send]        发消息
⚠️            警告（重点看）
Traceback     异常（必须处理）
```
