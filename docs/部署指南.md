# 部署指南

从零到上线。

---

## 一、准备

### 机器要求

| 项 | 最低 | 推荐 |
|---|---|---|
| CPU | 1 核 | 2 核+ |
| 内存 | 512 MB | 1 GB+ |
| 磁盘 | 2 GB | 10 GB+ |
| 系统 | 任意 Linux | Debian 12/13 |
| Python | 3.12 | 3.13 |

内存说明：常驻 36 MB，20 客户并发峰值约 200 MB。512 MB 能跑，但留点余量更好。

### 需要的账号

1. **QQ 机器人** — [q.qq.com](https://q.qq.com/) 注册，个人主体可选
2. **中转站** — 任意 OpenAI 兼容的 API 站点
3. **（可选）embedding 服务** — 不配就退回关键词检索

---

## 二、创建 QQ 机器人

1. 登录 [q.qq.com](https://q.qq.com/)，创建机器人
2. 拿到 **AppID** 和 **AppSecret**
3. 在「开发设置」里配置：
   - **IP 白名单**：填你的服务器公网 IP
   - **消息接收方式**：WebSocket（不要选 Webhook）
4. 在「功能配置」里开启**私聊**权限

### 关于体验用户

QQ 个人主体的机器人默认只能用「体验用户」名单，名额通常 **20 个**。

扩容需要企业认证。这是平台限制，不是本项目限制。

配置路径：开发管理 → 体验成员 → 添加 QQ 号。

---

## 三、安装

```bash
# 拉代码
git clone https://github.com/your-name/qq-companion.git
cd qq-companion

# 建虚拟环境
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 验证依赖
.venv/bin/python -c "import aiohttp, websockets, cryptography, numpy; print('ok')"
```

## 四、配置

### 生成加密密钥

```bash
.venv/bin/python -m companion.cli gen-secret
```

输出类似：

```
COMPANION_SECRET=<一串 base64>
```

**这一步必须做。** 没有它客户的 key 会明文存储。

> ⚠️ **备份这个密钥。** 丢失后所有客户的 key 都无法解密，
> 必须让每个人重新绑定。不要提交到 git。

### 写配置文件

```bash
sudo mkdir -p /etc/qq-companion
sudo cp deploy/env.example /etc/qq-companion/env
sudo chmod 600 /etc/qq-companion/env
sudo editor /etc/qq-companion/env
```

必填项：

```bash
QQ_APP_ID=你的AppID
QQ_APP_SECRET=你的AppSecret
COMPANION_SECRET=上一步生成的密钥
COMPANION_API_BASE=https://你的中转站/v1
COMPANION_BIND_URL=https://你的域名/bind
```

可选项：

```bash
# embedding（强烈建议配，否则检索召回率从 100% 掉到 70%）
COMPANION_EMBED_ENABLED=1
COMPANION_EMBED_API_BASE=https://api.siliconflow.cn/v1
COMPANION_EMBED_API_KEY=sk-xxx
COMPANION_EMBED_MODEL=BAAI/bge-m3
```

### 建数据目录

```bash
sudo useradd -r -s /bin/false qqcompanion
sudo mkdir -p /var/lib/qq-companion
sudo chown qqcompanion:qqcompanion /var/lib/qq-companion
```

## 五、首次运行

```bash
# 前台跑（用 systemd 用户身份，确保路径权限一致）
sudo -u qqcompanion env $(sudo grep -v "^#" /etc/qq-companion/env | xargs) \
  .venv/bin/python -m companion.main
```

看到这些就说明成功了：

```
[migrate] ...            ← 建表
[vector] 已启用 BAAI/bge-m3 (1024维)    ← 或者"已关闭"
[gw] READY 登录成功      ← 关键
```

按 `Ctrl+C` 停掉。

### 如果没连上

| 错误 | 原因 |
|---|---|
| `401` 或 `无效的 appid` | AppID/AppSecret 填错 |
| `IP 不在白名单` | 后台没配服务器 IP |
| `连接超时` | 防火墙挡了出站 443 |
| `intents 无权限` | 后台没开私聊权限 |

## 六、装成系统服务

```bash
sudo cp deploy/qq-companion.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now qq-companion

# 确认
sudo systemctl status qq-companion
sudo journalctl -u qq-companion -f
```

### 服务配置说明

`deploy/qq-companion.service` 里几个关键项：

```ini
MemoryMax=768M          # 内存硬上限，超了会被 OOM kill
Restart=always          # 崩溃自动重启
RestartSec=5
```

如果客户数超过 50，把 `MemoryMax` 调到 `1536M`。

## 七、配置绑定页

客户的 key 通过网页绑定，所以需要一个**能公网访问**的地址。

### 方式 A：Nginx 反代（推荐）

服务默认监听 `127.0.0.1:18401`。

```nginx
server {
    listen 443 ssl http2;
    server_name bot.example.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location /bind {
        proxy_pass http://127.0.0.1:18401;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

对应配置：

```bash
COMPANION_BIND_URL=https://bot.example.com/bind
COMPANION_BIND_HOST=127.0.0.1
COMPANION_BIND_PORT=18401
```

### 方式 B：Caddy（更简单，自动 HTTPS）

```
bot.example.com {
    reverse_proxy /bind* 127.0.0.1:18401
}
```

### 方式 C：直接暴露端口（不推荐）

```bash
COMPANION_BIND_URL=http://你的IP:18401/bind
COMPANION_BIND_HOST=0.0.0.0
```

**没有 HTTPS 时 key 在传输中是明文**，不要用于生产。

### 验证

浏览器打开 `https://你的域名/bind?code=TEST`，应该看到「绑定码无效」的提示 —— 说明页面通了。

### 跑自测

```bash
TEST_REAL_KEY=sk-你的密钥 COMPANION_ROOT=. \
  .venv/bin/python tests/selftest.py
```

应该看到：

```
通过 57 项，失败 0 项
```

### 真实测试

1. 把你自己加进体验用户
2. 私聊机器人发 `/start`
3. 发 `/setkey`，点链接绑定
4. 发 `/model`，选一个
5. 发「你好」

### 上线检查

```bash
# 无平台兜底 key（必须通过）
.venv/bin/python -m companion.cli assert

# key 巡检
.venv/bin/python -m companion.cli check-keys

# 无异常
sudo journalctl -u qq-companion --since "10 min ago" | grep -c Traceback
```

## 九、日常运维

### 每天

```bash
sudo systemctl status qq-companion | grep Memory
sudo journalctl -u qq-companion --since "1 day ago" | grep -cE "Traceback|⚠️"
```

第二个命令**应该是 0**。特别注意 `无 msg_id` 这类警告 —— 它意味着在消耗宝贵的主动消息配额。

### 每周

```bash
# 备份
.venv/bin/python -m companion.cli backup /var/backups/qq-companion

# key 巡检（失效的提前通知客户）
.venv/bin/python -m companion.cli check-keys

# 看整体统计
.venv/bin/python -m companion.cli stats
```

### 自动备份

```bash
sudo crontab -u qqcompanion -e
```

```cron
0 4 * * * cd /opt/qq-companion/app && /opt/qq-companion/venv/bin/python -m companion.cli backup /var/backups/qq-companion >> /var/log/qq-companion-backup.log 2>&1
```

`cli backup` 使用 SQLite 在线备份 API，**不停机、不锁库**。

### 升级

```bash
cd qq-companion
git pull

# 重新部署
sudo rm -rf /opt/qq-companion/app/companion
sudo cp -r companion /opt/qq-companion/app/
sudo chmod -R a+rX /opt/qq-companion/app

sudo systemctl restart qq-companion
```

数据库迁移在启动时自动执行（`_migrate()`），不需要手动跑 SQL。

## 十、故障排查

### 机器人完全不回复

```bash
# ① 服务在吗
sudo systemctl is-active qq-companion

# ② 连上了吗（看最近一次 READY）
sudo journalctl -u qq-companion | grep "READY" | tail -1

# ③ 有收到消息吗
sudo journalctl -u qq-companion | grep "\[in\]" | tail -5

# ④ 有报错吗
sudo journalctl -u qq-companion -n 100 | grep -A5 Traceback
```

**第 ③ 步是关键**：如果 `[in]` 有记录但没有回复，问题在生成端；如果连 `[in]` 都没有，问题在网关。

### 回复很慢

正常 2.5–3.5 秒。如果超过 10 秒：

```bash
# 看是不是检索慢
sudo journalctl -u qq-companion | grep "vector" | tail -20
```

### 内存持续上涨

```bash
sudo systemctl status qq-companion | grep Memory
```

如果持续增长不回落：

```bash
# 重启观察是否复现
sudo systemctl restart qq-companion
```

若复现，请附上日志提 issue。

### 记不住事

```bash
# 向量索引状态
sudo journalctl -u qq-companion | grep "\[vector\]" | tail -20
```

常见原因：

- `COMPANION_EMBED_API_KEY` 没配或失效 → 退回关键词检索（召回率 70%）
- embedding 服务欠费

### 数据库损坏

```bash
sqlite3 /var/lib/qq-companion/data.db "PRAGMA integrity_check;"
```

正常返回 `ok`。如果损坏，用最近的备份恢复。

### 主动消息配额耗尽

症状：日志出现大量 `无 msg_id`，之后客户发消息也收不到回复。

**原因**：有代码路径没传 `msg_id`，把主动消息配额用光了。

```bash
# 统计
sudo journalctl -u qq-companion | grep -c "无 msg_id"
```

正常应该 **0**。非 0 请报 issue 并附上调用栈。

## 十一、安全建议

1. **`/etc/qq-companion/env` 权限 600**，属主 root
2. **数据库目录只给 `qqcompanion` 用户**，不要给 shell
3. **绑定页必须 HTTPS**
4. **定期备份 `COMPANION_SECRET`**（离线保存）
5. **不要把 `env` 提交到 git**
6. **限制 SSH 来源 IP**
7. **防火墙只开 22 / 443**

### 检查暴露面

```bash
# 从外部扫（应该只有预期的端口）
nmap -p 1-10000 你的IP

# 确认绑定页没有多余路径
curl -I https://你的域名/bind
```

## 十二、卸载

```bash
sudo systemctl disable --now qq-companion
sudo rm /etc/systemd/system/qq-companion.service
sudo systemctl daemon-reload

# 数据（想保留就跳过这行）
sudo rm -rf /var/lib/qq-companion

sudo rm -rf /opt/qq-companion
sudo rm -rf /etc/qq-companion
sudo userdel qqcompanion
```

**卸载前建议先让客户 `/export` 导出数据。**
